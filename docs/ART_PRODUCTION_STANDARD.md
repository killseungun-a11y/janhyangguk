# 잔향국 아트 에셋 제작 정본 v1.0

> 이 문서는 잔향국에서 실제 게임에 적용하는 이미지 자산의 제작 규격과 1시간 주기 자동 생산 작업의 기준을 정의한다.

## 1. 적용 이미지 자산

잔향국의 게임 적용 이미지 자산은 아래 3계열로 관리한다.

1. **일러스트**
   - 컷씬 일러스트
   - 이벤트 일러스트
   - 잔향 도감용 일러스트
2. **잔향 작업용 2D**
   - 관리 격실에 수용된 잔향의 실제 플레이용 이미지
3. **직원 SD 캐릭터 애니메이션**
   - `idle / walk / work` 중심의 플레이용 애니메이션

---

# 2. 일러스트

## 2.1 공통 규격

- 해상도: **1024 × 1536**
- 형식: **PNG**
- 방향: **세로형**
- 표현: **완성형 2D 반실사 일러스트**
- 색감: 낮은 채도
- 주조색: 차콜 / 블랙 / 더티 아이보리 / 콘크리트 그레이 / 뮤트 네이비
- 제한 포인트: 다크 레드 / 녹슨 금속 / 낡은 금색
- 분위기: 현대 관리시설 + 동양 오컬트

### 금지

- 3D 렌더
- 피규어/장난감 같은 질감
- 과도한 광택
- 밝은 판타지풍
- 과도한 네온 사이버펑크
- 원색 위주의 화려한 색 구성
- 기존 캐릭터/잔향 디자인의 임의 변경

## 2.2 잔향 도감용 일러스트

잔향마다 도감용 일러스트를 별도 자산으로 관리한다.

### 용도

- 잔향 도감
- 정보 해금
- 기록 열람
- 잔향 소개
- 스토리 자료

### 기준

- 잔향 자체의 정체성과 실루엣을 가장 명확하게 보여준다.
- 격실 플레이 화면일 필요는 없다.
- 사물형 / 인간형 / 괴물형 / 비정형을 모두 허용한다.
- 사물형에 눈·입·팔다리를 억지로 붙이지 않는다.
- 괴물형과 인간형도 의도적으로 배제하지 않는다.
- 잔향의 핵심 물성과 기괴함이 명확해야 한다.

### 저장 예시

```text
assets/anomalies/one-stroke/codex/one-stroke_codex.png
assets/anomalies/third-bell/codex/third-bell_codex.png
```

# 3. 잔향 작업용 2D

잔향은 관리시설의 격실에 수용되어 직원이 들어가 작업을 수행하는 대상이다.

도감용 일러스트와 별도로 **실제 관리 플레이용 2D 이미지**를 제작한다.

## 3.1 기본 구조

```text
[관리 격실 + 격실에 수용된 잔향]
                +
        [직원 SD 애니메이션]
                ↓
           실제 관리 장면
```

직원은 작업용 2D 이미지 안에 미리 그리지 않는다.

## 3.2 규격

- 해상도: **1024 × 1536**
- 형식: **PNG**
- 방향: **세로형**
- 완성형 2D 공간 이미지
- 동일 잔향의 상태 변화는 **동일 카메라 구도** 유지
- 동일 잔향의 상태 변화는 **동일 격실 구조** 유지

## 3.3 격실 구성

최소한 다음 공간 정보가 자연스럽게 읽혀야 한다.

- 벽
- 바닥
- 출입구
- 조명
- 관찰 또는 관리시설 요소

UI 자체는 이미지 안에 그리지 않는다.

직원 SD가 위에 합성되는 것을 고려하여 다음을 확보한다.

- 직원이 설 수 있는 바닥 공간
- 잔향으로 접근할 수 있는 공간
- 작업 위치
- 직원과 잔향이 과도하게 겹치지 않는 구도
- 잔향이 무조건 화면 전체를 덮지 않는 크기
- 명확한 바닥 접지면

## 3.4 상태 변화

플레이어가 시각적으로 판단해야 하는 경우에만 아래 상태를 제작한다.

- `NORMAL`
- `OMEN`
- `UNSTABLE`
- `MELTDOWN`

모든 잔향에 4상태를 강제로 만들지 않는다.

상태 변화는 단순한 색상 필터가 아니라 해당 잔향의 실제 설정과 관리 규칙을 반영해야 한다.

예시:

- **한 획 NORMAL**: 조용한 한지와 수평 먹선
- **한 획 OMEN**: 먹선 가장자리가 출구 방향으로 미세하게 이동

즉, 플레이어가 `무언가 달라졌다`고 관찰할 수 있는 변화여야 한다.

### 저장 예시

```text
assets/anomalies/one-stroke/work/one-stroke_normal.png
assets/anomalies/one-stroke/work/one-stroke_omen.png
assets/anomalies/one-stroke/work/one-stroke_unstable.png
assets/anomalies/one-stroke/work/one-stroke_meltdown.png
```

# 4. 직원 SD 캐릭터 애니메이션

## 4.1 공통 규격

- 해상도: **1024 × 1024**
- 형식: **투명 PNG**
- 전신
- 비율: **2.8 ~ 3.2등신 반SD**
- 모든 프레임 동일 캔버스
- 모든 프레임 동일 캐릭터 크기
- 모든 프레임 동일 발 기준 위치
- 기존 캐릭터 원화를 그대로 SD화

## 4.2 스타일

- 귀엽지만 밝은 마스코트풍 금지
- 어둡고 피곤한 기관 직원 느낌 유지
- 검정 / 차콜 / 회색 / 탁한 남색 중심
- 과도한 머리 크기 금지
- 2등신 금지
- 피규어 / 장난감 느낌 금지
- 플라스틱 광택 금지

## 4.3 기본 애니메이션

- `idle`: 2~4프레임
- `walk`: 4프레임
- `work`: 3~4프레임

한 번의 생산 단위에서는 **한 직원 + 한 상태**를 완성된 세트로 제작한다.

### 파일 예시

```text
assets/employees/hajin/walk/
├─ hajin_walk_01.png
├─ hajin_walk_02.png
├─ hajin_walk_03.png
└─ hajin_walk_04.png
```

## 4.4 work 애니메이션

`work`는 실제 잔향 관리 작업으로 읽혀야 한다.

가능한 관리 행위 예시:

- 관찰
- 기록
- 측정
- 기기 조작
- 물리적 작업
- 조사
- 안정화 작업

단순히 팔만 흔드는 모션은 작업 애니메이션으로 보지 않는다.

# 5. 직원 제작 우선순위

```text
윤하진
→ 박도겸
→ 백서아
→ 최민호
→ 한세린
→ 정태린
→ 오지후
→ 노연우
→ 강시온
→ 백나윤
```

기본 상태 제작 순서는 다음과 같다.

```text
idle → walk → work
```

이미 완성된 상태는 건너뛴다.

---

# 6. 전체 생산 우선순위

기본 우선순위는 다음과 같다. 단, 현재 게임 구현에서 더 시급한 자산이 있으면 그 자산을 우선한다.

1. 실제 게임에서 현재 필요한데 없는 이미지
2. 게임에 등장할 잔향의 도감용 일러스트
3. 해당 잔향의 NORMAL 작업용 2D
4. 직원 idle
5. 직원 walk
6. 직원 work
7. 플레이 판단에 필요한 잔향 OMEN
8. 필요한 UNSTABLE
9. 필요한 MELTDOWN
10. 신규 컷씬 / 이벤트 일러스트

---

# 7. 기존 디자인 보호

이미 승인된 디자인은 임의로 재설계하지 않는다.

특히 다음 요소를 유지한다.

- 캐릭터 얼굴
- 헤어스타일
- 복장
- 안경
- 장신구
- 잔향 실루엣
- 주요 색상
- 잔향의 핵심 물성

기존 승인된 `CUT01 / CUT02 / CUT03` 등 정본 컷씬은 명시적인 교체 지시가 없으면 다시 만들거나 덮어쓰지 않는다.

---

# 8. 중복 방지

파일명만 보고 판단하지 않는다.

GitHub의 실제 폴더와 기존 자산을 확인하여 아래 항목의 완성본 존재 여부를 확인한다.

- 동일 캐릭터
- 동일 상태
- 동일 잔향
- 동일 용도

이미 완성된 항목이라면 건너뛰고 다음 미완성 항목을 선택한다.

---

# 9. GitHub 저장 규칙

이미지를 생성한 뒤 `assets/asset-routing.json`을 확인하여 정본 경로에 저장한다.

### 직원

```text
assets/employees/hajin/idle/
assets/employees/hajin/walk/
assets/employees/hajin/work/
```

### 잔향 도감

```text
assets/anomalies/third-bell/codex/
```

### 잔향 작업용 2D

```text
assets/anomalies/third-bell/work/
```

### 컷씬

```text
assets/cutscenes/
```

분류가 아직 확정되지 않은 경우에만 다음을 사용한다.

```text
assets/inbox/
```

# 11. 커밋 규칙

한 번의 실행에서 만든 **하나의 완성 단위**는 하나의 GitHub 커밋으로 묶는다.

예시:

```text
assets: add hajin walk animation
assets: add third bell codex illustration
assets: add third bell normal work scene
```

업로드 직전 최신 `main` HEAD를 다시 확인한다.

다른 변경사항이 발생했다면 최신 상태를 기준으로 충돌 없이 커밋한다.

**강제 push는 사용하지 않는다.**

# 12. 1시간 주기 자동 생산 프롬프트

아래 프롬프트를 1시간마다 실행하는 아트 생산 작업의 정본으로 사용한다.

```text
잔향국 게임용 아트 에셋을 1회 생산하라.

먼저 GitHub 저장소 `killseungun-a11y/janhyangguk`의 최신 `main` 브랜치를 확인하고,
`assets/asset-routing.json` 및 현재 존재하는 에셋을 검사한다.

이미 제작된 에셋과 중복되지 않도록
이번 실행에서는 "다음으로 필요한 미완성 에셋 1개 또는 애니메이션 1세트"만 선정하여 완성한다.

게임에 실제 적용하는 이미지 자산은 아래 3계열만 제작한다.

1. 일러스트
   - 컷씬
   - 이벤트
   - 잔향 도감용 일러스트
2. 잔향 작업용 2D
   - 관리 격실에 수용된 잔향의 실제 플레이 이미지
3. 직원 SD 캐릭터 애니메이션
   - idle / walk / work

[일러스트]
- 1024×1536 PNG 세로형
- 반실사 2D
- 낮은 채도
- 차콜 / 블랙 / 더티 아이보리 / 콘크리트 그레이 / 뮤트 네이비 중심
- 현대 관리시설 + 동양 오컬트 분위기
- 3D 렌더, 피규어, 밝은 판타지, 과도한 네온 금지

[잔향 도감용 일러스트]
- 잔향 자체의 정체성, 물성, 실루엣을 가장 잘 보여주는 소개용 원화다.
- 격실 화면일 필요는 없다.
- 사물형 / 인간형 / 괴물형 / 비정형 모두 허용한다.
- 사물형에 눈·입·팔다리를 억지로 추가하지 않는다.
- 괴물형과 인간형도 의도적으로 배제하지 않는다.

[잔향 작업용 2D]
- 1024×1536 PNG 세로형
- 반드시 관리 격실 + 격실에 수용된 잔향 구조로 제작한다.
- 직원은 이미지에 미리 그리지 않는다.
- 직원 SD가 위에 합성될 수 있도록 바닥, 접근 공간, 작업 위치를 확보한다.
- 동일 잔향의 상태 변화는 동일한 카메라 구도와 동일한 격실 구조를 유지한다.
- 필요한 경우 NORMAL / OMEN / UNSTABLE / MELTDOWN 상태를 제작한다.
- 모든 상태를 강제로 만들지 않는다.
- 상태 변화는 단순 색상 필터가 아니라 실제 관리 규칙과 설정을 반영한다.

[직원 SD 캐릭터 애니메이션]
- 1024×1024 투명 PNG
- 2.8~3.2등신 반SD 전신
- 모든 프레임 동일 캔버스 / 동일 캐릭터 크기 / 동일 발 기준 위치
- 기존 캐릭터 디자인 유지
- 2등신, 장난감, 피규어, 플라스틱 광택 금지
- idle 2~4프레임
- walk 4프레임
- work 3~4프레임
- 한 번의 실행에서는 한 직원의 한 상태 세트를 완성한다.
- work는 관찰 / 기록 / 측정 / 기기 조작 / 조사 / 안정화 등 실제 관리행위로 읽혀야 한다.

직원 제작 순서:
윤하진 → 박도겸 → 백서아 → 최민호 → 한세린 → 정태린 → 오지후 → 노연우 → 강시온 → 백나윤

상태 제작 순서:
idle → walk → work

2. 잔향 도감용 일러스트
3. 해당 잔향 NORMAL 작업용 2D

hajin_walk_02.png
```

# 13. 완료 조건

한 번의 자동 생산 실행은 아래가 모두 완료되어야 끝난 것으로 본다.

1. 최신 GitHub 확인
2. 기존 에셋 확인
3. 중복 확인
4. 다음 제작 대상 선정
5. 실제 이미지 생성
6. 이미지 규격 검증
